# 우리 동네 생태 퀴즈

## 프로젝트 개요
Python 표준 라이브러리로 만드는 콘솔 퀴즈 게임입니다.

## 주제 선정 이유
시민생물조사단 활동에서 만난 생물과 환경 지식을 퀴즈로 복습하기 위해 선택했습니다.

## 실행 방법
Python 3.10 이상이 필요합니다. 외부 라이브러리 설치는 필요하지 않습니다.

```bash
git clone https://github.com/minjung-workshop/eco-quiz-m2.git
cd eco-quiz-m2
python3 main.py
```

## 기능 목록
1. 퀴즈 풀기: 등록된 문제를 풀고 정답 여부와 최종 점수를 확인합니다.
2. 퀴즈 추가: 문제, 선택지 4개, 정답 번호를 입력하고 파일에 저장합니다.
3. 퀴즈 목록: 등록된 문제를 번호와 함께 확인합니다.
4. 점수 확인: 완료한 게임의 최고 점수를 확인합니다.
5. 종료: 퀴즈와 점수를 저장하고 종료합니다.

점수는 정답 수를 전체 문제 수로 나눈 뒤 100을 곱하고 반올림합니다.
아직 게임을 완료하지 않았다면 기록이 없다는 안내를 표시합니다.
진행 중인 게임을 중단하면 해당 게임의 점수는 기록하지 않습니다.

## 파일 구조
| 파일 또는 폴더 | 역할 |

## 데이터 파일 설명
데이터는 프로젝트 루트의 state.json에 UTF-8 인코딩으로 저장합니다.
실행한 터미널의 현재 위치와 관계없이 game.py가 있는 폴더를 기준으로 찾습니다.

```json
{
  "quizzes": [
    {
      "question": "문제 내용",
      "choices": ["선택지 1", "선택지 2", "선택지 3", "선택지 4"],
      "answer": 1
    }
  ],
  "best_score": null
}
```

- quizzes: 문제 목록입니다. 각 문제에는 question, choices, answer가 있습니다.
- choices: 비어 있지 않은 문자열 4개입니다.
- answer: 화면에 표시되는 정답 번호인 1~4의 정수입니다.
- best_score: 0~100의 최고 점수입니다. 게임 완료 기록이 없으면 null입니다.
- 퀴즈 추가, 최고 점수 갱신, 프로그램 종료 시 저장합니다.
- 임시 파일 state.json.tmp에 먼저 작성한 뒤 state.json을 교체합니다.
- 파일이 없으면 기본 퀴즈로 시작합니다.
- JSON 문법이나 데이터 형식이 잘못되면 안내하고 기본 퀴즈로 시작합니다.
- 손상 파일은 state.corrupt-시간값.json으로 보관합니다.
- 읽기 오류나 손상 파일 보관 실패 시 기존 파일 보호를 위해 저장하지 않습니다.
- 쓰기 오류가 발생하면 저장 실패 안내를 표시합니다.

## 입력 및 예외 처리
숫자 입력은 앞뒤 공백을 제거하고 빈 입력, 숫자가 아닌 입력,
허용 범위를 벗어난 입력을 검사하여 다시 입력받습니다.
문제와 선택지도 빈 내용으로 등록할 수 없습니다.
Ctrl+C 또는 EOF가 발생하면 안내하고 가능한 경우 저장 후 종료합니다.

## 커밋 단위와 메시지 규칙
최소 10개 이상의 의미 있는 커밋을 남기는 것을 기준으로 합니다.
메뉴, Quiz 클래스, 기본 문제, 퀴즈 풀이, 등록, 목록,
최고 점수, 파일 저장 등 기능별로 구현하고 확인한 뒤 커밋합니다.
서로 다른 목적의 변경은 가능한 한 별도 커밋으로 분리합니다.
커밋 수만 늘리는 빈 커밋이나 의미 없는 변경은 사용하지 않습니다.

메시지 형식은 `유형: 구체적인 변경 요약`입니다.

| 유형 | 사용 목적 | 예시 |
|---|---|---|
| Feat | 새 기능 구현 | Feat: 최고 점수 갱신과 기록 조회 구현 |
| Fix | 오류 수정 | Fix: 퀴즈 플레이 캡처 파일 이름 수정 |
| Refactor | 동작을 유지하며 구조 개선 | Refactor: QuizGame 클래스로 게임 관리와 입력 처리 분리 |
| Test | 검사 코드 또는 검증 기록 추가 | Test: 입력 오류와 안전 종료 및 저장 파일 복구 확인 |
| Docs | 문서와 증거 자료 정리 | Docs: 실행 방법과 데이터 저장 구조 설명 |
| Chore | 프로젝트 초기 설정 등 | Chore: 생태 퀴즈 프로젝트 초기 설정 |

실제 커밋 수, 병합을 제외한 커밋 목록, 병합 그래프는
[Git 변경 이력 텍스트](logs/09-git-history.txt)에서 확인할 수 있습니다.

## 클래스를 사용한 이유
### Quiz: 개별 문제의 추상화와 재사용
Quiz는 문제, 선택지, 정답을 하나의 객체로 묶습니다.
이는 실제 퀴즈에서 필요한 데이터와 동작만 코드로 표현하는 추상화입니다.
각 문제를 별도 변수로 관리하는 대신 동일한 구조의 객체로 다룹니다.

문제가 달라도 display()와 check_answer()를 재사용할 수 있습니다.
새 퀴즈를 추가할 때 출력과 정답 판정 코드를 다시 작성할 필요가 없습니다.
to_dict()와 from_dict()는 객체와 저장 데이터 사이의 변환을 담당합니다.

### QuizGame: 게임 전체 상태와 진행 관리
QuizGame은 퀴즈 목록과 최고 점수를 속성으로 보관하고,
메뉴와 게임 진행을 메서드로 관리합니다.
개별 문제의 정답 판정은 Quiz에 맡겨 역할을 분리합니다.

- show_menu(), run(): 메뉴 표시와 사용자 선택에 따른 실행
- play(): 퀴즈 출제, 정답 수와 점수 계산, 최고 점수 갱신
- add_quiz(), list_quizzes(): 문제 등록과 목록 조회
- show_score(): 최고 점수 조회
- load_state(), save_state(): 파일 불러오기와 저장

이 구조에서는 문제 출력 방식을 바꿀 때 Quiz를,
메뉴 흐름을 바꿀 때 QuizGame을 중심으로 수정할 수 있습니다.
입력 검사는 input_utils.py의 read_number(), read_text()를 재사용합니다.
